# 从输入到成品的对话引导

## 维护一份简短创作记录

在当前对话内记录，不要求用户逐项必填，不自动写入持久文件。面向用户的选择采用[可选填设计表](selection-table.md)，创作记录是助手对已定条件、自选项和推荐值的汇总。

| 字段 | 记录方式 |
| --- | --- |
| 内容类型 / 媒介 / 用途 | 人像 / 写实摄影 / 头像；未知就保持未知 |
| 人物基础五项 | 人数、性别、年龄、来源地区/文化背景、身份/场景角色；每项记录已定、推荐或不限定，多人分别记录 |
| 创作方向 | 主风格、核心氛围、主体/辅助/背景层级；历史题材另记风格化、文物参考或严谨复原 |
| 空间草图 | 复杂场景记录相机位置、实体支撑面、远近高低、遮挡与尺度参照；按[校验规则](scene-validation.md)审查，不要求用户填技术参数 |
| 用户已定 | 原有明确内容，作为保留条件 |
| 待决定 | 会明显改变画面的最多几个关键缺项 |
| 助手建议 | 用户尚未指定、可替换的补充 |
| 当前版本 | 本轮提示词与相对上一轮的修改 |

用户改口时更新对应条件。例如“换成海边”替换场景，不连带改变已定服饰、年龄或画幅。用户要求“换个感觉”时，提出具体能改变氛围的选项，例如光色或风格，保留其他设定。

## 根据输入走不同路径

| 输入情况 | 本轮行动 | 何时交付 |
| --- | --- | --- |
| 只有主体，如“一个女性” | 展示相关设计表，画面方向也给候选和推荐，造型属性分项可选 | 用户提交任意选择或说“生成”后，未选项按推荐，直接合成 |
| 短句有方向，如“雨夜街头的女性写真” | 先列已定条件，表中只提供适用的可调整项，不重问人像/摄影/雨夜 | 一次提交即可进入完整设计 |
| 完整提示词或“只润色” | 提取保留条件，消除赘余、补必要空间关系；不另开问卷 | 本轮直接给成品及必要的修改说明 |
| “直接给 / 不要问 / 你决定 / 随便” | 不提问，沿用明确条件，选择少量协调的默认值 | 本轮直接给成品 |
| 用户问术语 | 先解释这个术语，给对照及图解链接；不启动全套创作提问 | 解释后可让用户选效果，或按其要求立即改词 |
| 只改一个元素 | 替换该元素和必然受影响的细节 | 本轮直接给更新版本 |

设计表是可选填的，不设逐项回答配额。用户未回复时保持待选，不虚构选择；用户提交部分选择或“生成”后，立即采用未选项的推荐，不再等表格填满。用户愿意深入设计时，再讨论其在意的维度。

## 问题长什么样

默认将可独立选择的要素放在同一张[选择表](selection-table.md)，每项给3～5个直观候选、一个明确推荐和简短理由，允许自由描述。表格不会自动提交或保存，用户在聊天中回复改选项即可。关键歧义或冲突需要单独澄清时，每次只问一个决定。不要让用户先提供焦距、光圈、色温值或专业构图术语。

组织表格时优先考虑以下方向，已有明确条件就直接列为已定：

1. **画面方向 / 媒介**：“窗边生活照片、街头时尚照片，还是故事人物插画？”
2. **观看重点 / 景别**：“更想看清表情（半身），还是看完整穿搭（全身）？”
3. **情绪 / 光色**：“明亮温暖、自然平和，还是偏暗有故事感？”

服饰、场景、动作已明确时无需再问。人物基础五项必须在已定条件或人物设定表中覆盖，未定项可推荐或不限定，不能被发色、服装等选项挤掉。地区背景不与固定五官、肤色绑定；脸型、身材和肤色等可见外形按场景需要另列。

## “不懂”和“想看例子”

采用同一个小结构：

> **通俗差异**：背景能不能看清。
> A. 看得清书架和窗户：人物与环境共同清晰（较深景深）。
> B. 看得出是书店，但字和远处细节柔化：背景轻微虚化。
> C. 远处只剩模糊色块，脸最突出：背景明显虚化（可用浅景深表达）。
> 日常环境人像可以先选 B；要强调表情可以选 C。

要看示意图时，链接 `assets/portrait-terms.html#depth-of-field` 的实际本地路径。其他锚点见[术语表](portrait/glossary.md)。若当前界面无法打开 HTML，直接展示 A/B 短句或内联示意，不能声称已向用户展示真实照片。

用户要看**真实摄影参考**时，能联网就查可公开访问的来源并附原始链接，保留图片授权语境；无浏览能力时说明限制并提供可搜索的词。用户要看**同一主体的生成对照**时，可使用可用的出图工具，每组只改变所解释的因素，并把结果标为生成示例；不能把不同模特、不同背景的图当作严格单变量比较。

## 默认值怎么用

助手可提供与主题协调的具体设计，如服装配色、可见材质、动作阶段、道具位置、背景层次、机位、光线方向与清晰范围。这些是可替换建议，不是把87项全问用户。不要把“日常服饰、简单场景、柔和光”当作每张图的固定答案；要描述这张图的衣物、场景和光影如何具体呈现。“成年”也属于助手补充，除非原文已写；用户明确要求儿童或老人时沿用原年龄并选择合适场景。

从最能改变画面的要素开始，按场景展开到足以执行的细节；“动作”可以需要多句表达，不能因已列出若干参数就停止。避免固定“8K、杰作、获奖、85mm、f/1.2”等套词。成品后用一行指出重要补充项，无需逐字列出全部扩写。用户要求只输出提示词正文时，不另加说明，但也不声称这些细节由用户指定。

## 结束提问后，助手继续设计

用户提交选择或说“按推荐生成”后，先合并明确选择和表中推荐，再完成[成品设计检查](output-contract.md)。先组织这张图的视觉重点，不把表格逐行拼成成品，也不继续用问卷把专业工作交回用户。若此前只做了风格和景别选择且还未展示设计表，先给一张适用的可选表；明确要求直接成品时跳过。

例如骑电瓶车：在保留微笑和耳机的前提下，选择能看见它们的拍摄方位，安排双手与车把、身体与车座、双脚与踏板的关系，让完整车轮有落地依据，给行进方向留出空间，再决定道路纵深、光线方向和环境清晰范围。上述细节可以由助手做协调建议，不必变成十个问题。

用户说“有点简单 / 更专业 / 更丰富”时，优先补强原有画面的动作、空间、构图与光影，而不是换场景、换媒介、添加新故事或反复追问。用户给了参照文本时，学习它的具体程度，不复制其中的刻板外貌、重复修饰和未定候选项。

用户提供其他AI的点评时，把它当作待核查建议：采纳真实缺口，区分已有能力与新增要求。确认时代造型是否有依据，身份词能否变成可见细节；不照抄“稳定出图”、无样本评分、固定八段或整套通用负面词。保留用户对原作品已经明确的选择。

用户反馈比例、角度、遮挡或动作不合理时，先沿用已定人物与风格，按[场景校验](scene-validation.md)定位空间风险。已有图就检查实际可见结果；没有图只能给文字层面的可能原因。不要把所有问题归因于焦距，也不要只追加“不巨人、比例正确”而保留原布局。默认修正助手建议的构图；确有两个用户要求冲突时才问一个取舍问题。

## 冲突处理

- **明确的新要求替换旧要求**：“改成全身”覆盖此前的半身，其他保留。
- **同一画面内确实冲突**：“只拍脸部特写，同时鞋子完整可见”需要用户选观看重点。说清两个效果，只问这个冲突。
- **用户要求不要提问但存在冲突**：优先遵循最新且最具体要求；无可判断优先级时，交付 A/B 两条各自自洽的方案。允许说明时用一句话说明差别；只要一条时选最具体的主体呈现要求。
- **通常可以协调**：黑白与温暖情绪、逆光与面部可见、硬光与明亮画面并非必然冲突；可用叙事、补光、曝光关系等明确表达，不机械删除。
- **镜头、距离、景别冲突**：先保留可见效果，镜头数值只是可选表达；若用户明确要求技术参数，则说明组合限制并询问优先级。

## 从提问转入专业设计的条件

用户提交表格选择或明确让助手直接生成、现有条件无实质冲突时，进入专业设计；未选项沿用推荐，无需全部填写。完成[输出约定](output-contract.md)中适用的设计检查后交付。不是每张图都需要运动或复杂背景：纯色棚拍、静态头像应把深度用在表情、可见造型、光影和材质上。
