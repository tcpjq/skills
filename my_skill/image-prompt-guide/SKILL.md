# 图片提示词引导

把用户的想法整理为可复制、设计充分的图片提示词。默认用可选填的设计表呈现候选和推荐，用户只改自己在意的项目，未选项沿用推荐，助手负责专业展开。当前具备完整的**写真人像篇**；其他图片类型使用通用框架。

不要首次把全部资源载入对话，也不要把 87 项变成问卷。

若从 `image-idea-guide` 接到已选方案与“直接展开”的创意简报，保留已定角色、场景、动作、媒介和用途，直接走完整设计与合理性校验；用户希望继续选细节时才展示适用的选择表，不重启首轮创意菜单。

## 工作流程

1. **识别任务与已知条件。** 区分“写提示词 / 改提示词 / 解释术语 / 实际出图”。人像每次必查人数、性别、年龄、来源地区/文化背景、身份/场景角色五项，记录为用户已定、推荐或明确不限定；保留服饰、场景、动作、风格、构图、比例和限制。区分内容类型与表现媒介：人像不自动等于摄影，人物也可以是水彩或 3D。
2. **选择引导方式。** 新建或探索图片提示词时，默认展示[可选填设计表](references/selection-table.md)。基础五项中已定的列在表前，未定的给人物设定表，不能遗漏年龄、性别或来源入口；再按场景与景别给造型和画面表，各有候选、单一推荐和理由，两表一次提交。发色、上衣款式、上衣颜色等可分别改选。只有关键歧义或实质冲突才先问一个问题。只润色、只改一项、仅解释术语或明确直接成品时跳过整表，但不丢失已有基础设定。
3. **接收选择并应用默认。** 用户可用自然语言只改几项；本轮未提到的项目沿用已展示推荐，随后直接生成。回复“生成、继续、都按推荐”时，全部未自选项目用推荐。用户明确“不指定”或“不要”也属于有效选择。未回复则保持待选。用户已定条件始终高于推荐，不逐项追问已给默认值的项目。术语用通俗效果解释，如“人清楚、背景糊一些（浅景深）”。
4. **需要时解释或展示。** 先用一句话解释，再给两个对照效果和对应短句。在可链接本地文件的环境中，使用图解文件的实际绝对路径链接，可附稳定锚点。用户可自行打开 HTML；无法打开时，用文字对照或可用的内联图示继续。图形示意不等于生成图片；实际生成示例需用户请求且有工具可用。
5. **完成设计展开。** 结束提问后，按[输出约定](references/output-contract.md)先确定主风格、核心氛围和主体/辅助/背景层级，再补适用的人物造型、动作、空间、摄影、光色与材质。身份和抽象风格用少量可见细节支撑；时代或文化标签依[古装专项](references/portrait/historical-costume.md)区分创作与证据，现代题材不加载该篇。用户明确选择高于默认值。复杂动作读[人像设计](references/portrait/design-guide.md)对应部分，不能只复述输入或堆形容词。
6. **验证场景合理性（必经）。** 按[校验规则](references/scene-validation.md)检查写实单场景的机位、视域与遮挡、真实尺度和前后关系、动作支撑、视线、光影动态；复杂布局先明确相机和实体位置。主角重要不等于物理体型更大，画面下方不等于近处。未通过时先修助手默认的机位、景别与空间描述，再复查关联项；明确要求冲突时才询问取舍。多视图、平面设计与超现实作品按其艺术目标校验。没有生成图时只做文本方案判断。
7. **交付。** 默认给完整设计版，信息深度随场景需要调整；只有用户要求简洁或限字时才压缩。将候选项落实为明确选择，通常给一条中文成品提示词，再简短列出补充的默认值；约束、英文与平台参数按需提供。“直接给”只跳过提问，“只给提示词”只省略解释，两者不跳过合理性校验，也不自动降低设计深度。不会声称文字校验保证生成效果。

## 使用边界

- 提示词整理本身无需联网、安装依赖或调用出图工具；输出默认平台中立。
- 用户指定平台时才适配其格式；不确定的参数先查可用的官方文档，不能猜测版本语法。
- 参考图只提取可见画面要素；不从外貌推断身份、族裔、国籍、职业或性格。用户明确指定的虚构角色背景可保留。
- 不把其他类型强行套成人像摄影；当前没有专篇时明确使用通用框架，仍完成用户当前任务。
- 文字检查只能评估信息与内部一致性；没有实际生成样本时，不宣称稳定出图，不捏造成功率或图像效果评分。

## 快速示例

用户：“一个女性。”

回应：列出“已定：单人女性”，人物设定表补年龄、来源地区/文化背景与角色的选择和推荐，造型和画面表给画面方向、发型、发色、上衣款式、上衣颜色、场景、景别与光线。表后说明：“只改你在意的项目，未提到的按推荐；回复‘生成’即可全部用推荐。”

用户：“发色深棕，上衣浅蓝色衬衫，其他默认。”合并三项选择和其余展示推荐后，直接交付完整设计，不再逐项追问。

## 自检

人物基础五项是否都有状态？明确选择是否保留？风格、氛围与主次是否统一？身份与时代是否有依据？单一机位是否能看见指定内容，尺度、遮挡、动作和视线是否自洽？约束是否针对实际问题？维护时用[验收场景](tests/acceptance.md)复测。
